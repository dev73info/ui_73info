# 跑门禁（ui_73info）

## 一、两条命令

| 时机 | 命令 | 包含什么 |
| --- | --- | --- |
| 改一版就验一次（提交前） | `pnpm type-check && pnpm test` | `vue-tsc --build` + `vitest run` |
| 开 PR / 合并前 | `pnpm type-check && pnpm test` | 同 quick；涉及破坏性改动再加宿主仓的联动验证 |

只改文档、注释、`.claude/` 资产时不必跑全套，但**提交前至少跑一次 `pnpm type-check && pnpm test`** 确认没有顺手带坏代码。

## 二、逐项命令与判据

| 项 | 命令 | 判据 / 失败怎么办 |
| --- | --- | --- |
| 类型 | `pnpm type-check` | `vue-tsc --build`；**本库没有 build 步骤，这是唯一静态校验入口** |
| 单测 | `pnpm test` | `vitest run`，25 文件 / 152 条（含 7 条 `it.fails` 钉住的已知缺陷） |
| 联动 | 在 `../user_client` 跑 `pnpm type-check` + `pnpm test:ci` | 宿主以 link 依赖消费本库源码，props / 事件 / 令牌破了宿主会先炸 |
| lint / format | 暂无脚本 | 已知缺口：按仓库既有风格手写，不要引入新的格式化风格 |

## 三、按失败类别处置

1. **类型错**（`TS2xxx`）：不要用 `any` / `@ts-expect-error` 糊过去；先判断是类型声明错、还是真的取值可能为空
   （本仓开了 `noUncheckedIndexedAccess`，取数组/下标要显式判空）。
2. **lint 错**：修代码，**不要手写 `eslint-disable`**；既有存量走 `eslint-suppressions.json`（只减不增）。
3. **结构检查错**：说明本次新增了结构债——拆文件或改用令牌，**不要**把新条目写进基线
   （基线是迁移台账，只登记改造前就存在的条目）。
4. **契约漂移**：说明后端 spec 变了。重跑 `（本仓不涉契约）` 生成物后再看 diff 是否符合预期；
   如果后端还没产出 spec，门禁打印的是「未就绪」并放行——**那不是通过**，在 PR 里写明。
5. **单测失败**：先确认是本次改动引起的还是环境问题（`git stash` 后重跑一次对照）。
   不要为了变绿删断言或改成 `skip`；确实要跳过的，在 PR 里写明原因与恢复计划。

## 四、留证据

跑完把**真实输出**（末尾几行统计 + 失败项全文）贴进 PR 正文的「验证证据」一节。
不要写「门禁应该能过」「本地跑过没问题」这类没有输出的结论。

## 五、本仓特别提醒

- 本库**发源码不发构建产物**，`package.json` 入口指向 `src/`，别改回去。
- 令牌正本是 `src/styles/tokens.css`：本库内部也不许写裸色值。
- 改 props / 事件 / 插槽 / 令牌前先确认消费方（`../user_client`），跨仓同名分支一起改。
