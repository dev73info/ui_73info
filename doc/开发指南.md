## 一、环境与命令

只需要 Node ≥ 20.19 与 pnpm。

| 命令 | 说明 |
| --- | --- |
| `pnpm install` | 装依赖，只需一次 |
| `pnpm dev` | 起 playground（组件预览页），**端口 5180**，`strictPort` 打开——端口被占直接报错，不悄悄换端口 |
| `pnpm type-check` | `vue-tsc --build`。**本库没有 build 步骤**，这是唯一的自动校验入口 |

`pnpm type-check` 会检查 `.ts`、编译 `.vue` 并检查模板里的类型（含组件 props）、
生成声明文件。**改完代码必须跑一次**，它比任何手工检查都便宜。
`playground/` 也在检查范围内。

### playground

`pnpm dev` 起的是 `playground/`：一个把每个组件、每个 `tone`、两套主题都摆出来的单页，
用来肉眼比对。它**不是文档站**，刻意不做导航与分组，目的是一屏看完、切主题时盯着看变化。

几个验证要点：

- **切到 `dev`，看「成功」与「警示」是不是从绿/琥珀变成青/金**。若颜色不变，
  说明组件里写死了色值或引了 `--el-*`。
- **`md` 与 `sm` 按钮的高度应明显不同**（36px / 28px）。高度没变说明尺寸令牌没接上。
- **打开弹窗后**：Tab 应在弹窗内循环、Esc 关闭、关闭后焦点回到「打开弹窗」那颗按钮上、
  背景滚动被锁住（弹窗开着时 `body.style.overflow` 是 `hidden`）。
- **表单区**：直接点「提交」应四条都标红；把昵称填 `admin` 会触发异步校验
  （延迟 400ms 后报「该昵称已被占用」），填别的则通过。
- **下拉与日期面板**：面板应贴在选择器下方 4px 处、左边界对齐；靠近视口底部时应自动
  **翻到上方**；页面滚动时面板跟着锚点走。键盘：`↓` 展开、`↑↓` 移动高亮、`Enter` 选中并收起、`Esc` 收起。
- **表格**：表头底色是冷灰蓝而不是 Element 的暖灰；斑马纹、悬停、表头底色都必须是
  **不透明值**——把表格横向滚动一点，右侧固定列下面不能透出内容。拖动表头右边缘能改列宽。
- **日期面板标题可以点**：`2026 年 9 月` → `2026 年` → `2016 – 2027`，三级都能选。
- **`TMessage`**：提示条应出现在**右下角**，是**半透明色块 + 粗体文案 + 一枚 `×`**、
  没有图标；连点 7 次同一颗按钮，最多同时 5 条（超出挤掉最旧的）；
  把窗口拖窄到 640px 以下应挪到**顶部通栏**且进场方向变成自上而下。
  **`TMessageBox`** 连点两次会排队而不是叠在一起，且打开时背景锁定。

> 上面这些都可以在浏览器控制台直接复验，不必改代码。例如面板位置：
> `document.querySelector('.t73-select-panel--open').getBoundingClientRect()`。

playground 的样式也走 `--73-*` 令牌——它本身就是本库的一个消费方，
不要在它里面写裸色值。

> 手工验证主题也可以不进 playground：在浏览器控制台执行
> `document.documentElement.setAttribute('data-73-theme','dev')` 立刻能看到切换。

## 二、目录与命名约定

```
src/
  index.ts                    出口
  styles/                     样式（见下表）
  theme/index.ts              主题运行时
  primitives/                 行为原语，一个原语一个文件
  components/<Name>/          一个组件一个目录
    <Name>.vue                组件本体
    types.ts                  props / emits 的接口与字段说明
    index.ts                  再导出组件与类型
    context.ts                （可选）provide / inject 的上下文
    <局部模块>.ts             （可选）纯逻辑。如 TForm/validate.ts、TDatePicker/date.ts
  types/common.ts             跨组件共用类型（ComponentSize、Tone）
playground/                   pnpm dev 起的预览页（不属于发布内容）
```

一个组件目录里**多文件的边界**是「能不能单独测」：
`types.ts` 放接口，`context.ts` 放 inject 的键与形状，纯逻辑（校验引擎、日期格式化）
单独一个文件——它们都不依赖 Vue 的渲染，可以直接写单元测试。
样式一律写在 `.vue` 的 `<style scoped>` 里，不额外拆 `.css`。

| 样式文件 | 职责 |
| --- | --- |
| `styles/tokens.css` | 令牌层。**唯一的色值来源**，两套主题都在这里 |
| `styles/reset.css` | 样式底座，只作用于 `.t73` 类名空间 |
| `styles/alias.css` | 迁移兼容层（旧变量名 → `--73-*`）。`user_client` 全程没引过，现在无使用者；按计划应连同 `./alias.css` 出口一起删掉 |
| `styles/index.css` | 样式入口，只 `@import` 上面两份（不含 alias），对外是 `ui_73info/styles.css` |

命名规则：

- 组件名 `T` 前缀 + 大驼峰（`TButton`、`TFormItem`）。
- CSS 类名 `t73-` 前缀 + 中划线（`t73-button`、`t73-button__label`、`t73-button--solid`），
  BEM 风格。**前缀不能省**——它是这个库唯一的辨识标记，也是 `reset.css` 的钩子。
- 令牌 `--73-` 前缀 + 中划线语义名（`--73-ink-soft`、`--73-radius-card`）。
- 组件内部私有的中间变量用 `--t73-` + 组件名（`--t73-btn-solid`），
  只在该组件的样式里出现，不进令牌层。

## 三、编码规范

1. **SFC 元素顺序：`<script setup>` → `<template>` → `<style scoped>`**（与仓库既有约定一致）。
2. **禁 `any`**；类型导入一律用 `import type`（`@vue/tsconfig` 开着 `verbatimModuleSyntax`）。
3. **库内一律用相对路径**，不要 `@/`。理由见 [架构.md](架构.md) 第六节——宿主把 `@`
   指到它自己的 `src`，库内写 `@/` 会解析错目录。
4. **组件根元素必须带 `t73` 类**（`<button class="t73-button t73">`），
   它承载字体、墨色、`box-sizing` 基线。
5. **组件层禁止写裸色值、裸 px 的色相关值。** 颜色只从 `var(--73-*)` 取；
   确实需要一个新的色值档位时，**加到 `tokens.css` 并写明它从哪个源文件来**，
   不要在组件里就地写一个。
6. **不接受色值类 prop。** 组件暴露的是语义（`tone="success"`），不是颜色。
7. **`inheritAttrs: false` 的组件要把 `v-bind="$attrs"` 落到根元素上。** `TButton`
   （根是动态组件）、`TInput`（根是包裹用的 div）、`TDialog`（根是 Teleport，不是真实元素）
   都关掉了自动透传，不透传出去会导致调用方写的 `class` / `style` / `data-*` 被静默丢弃。
8. **注释写「为什么」而不是「是什么」**，与仓库其余部分一致；踩过的坑要写进去。

## 四、新增一个组件的步骤

以 `TWidget` 为例：

1. **先定语义，再定样式。** 这个组件在 user_client 里接替谁？它现有规格在哪个文件？
   把「旧写法 → 新写法」的对应关系写进 `types.ts` 的注释里（`TButton` 的 `variant`
   字段注释就是范例）。迁移时这行注释能省掉一整轮试错。
2. **建目录** `src/components/TWidget/`，写三个文件：`TWidget.vue`、`types.ts`、`index.ts`。
3. **组件里只用 `--73-*`。** 遇到缺口回头补令牌，补的时候写清楚来源。
   如果是**两套主题里取值不同**的档位，两边都要补；如果是与主题无关的（尺寸、字号），
   补到 `tokens.css` 第一节那个 `:root` 块里。
4. **需要交互行为时先看 `src/primitives/`** 有没有现成的（焦点陷阱、关闭行为、
   滚动锁定、稳定 id）。要新写原语就放到 `primitives/`，别写在组件里——
   下一个组件会需要同一个。
5. **在 `src/components/index.ts` 里加一行 `export * from './TWidget'`**，
   并在 `src/index.ts` 的 `components` 映射里登记（全局注册插件与测试批量挂载用）。
6. **在 `doc/架构.md` 或 `README.md` 的进度清单里把它从未实现挪到已实现。**
7. **跑 `pnpm type-check`。**

### 组件的必查项

- [ ] 根元素带 `t73` 类
- [ ] 类名是 `t73-` 前缀
- [ ] 没有任何裸色值
- [ ] `disabled` / 加载中这类状态**只降透明度或换令牌**，没有新开一组只用于禁用的颜色
- [ ] 键盘可达：可点元素是原生 `button` 或有 `tabindex` + 键盘处理
- [ ] 有 `:focus-visible` 样式，用 `var(--73-focus-ring)`
- [ ] 需要无障碍名称的（纯图标按钮、弹窗）有 `aria-label` 或 `aria-labelledby`
- [ ] 数字（金额、计数）带 `font-variant-numeric: tabular-nums`
- [ ] 表单控件注入了 `FORM_ITEM_CONTEXT`，能自动参与校验与 `id` 关联
- [ ] 关掉动效（`prefers-reduced-motion`）时有兜底——`reset.css` 已全局处理，组件不必重复

## 五、验证主题与组件

### 主题切换

在页面的 `<html>` 上改属性即可（**必须是 `<html>`**，原因见
[架构.md](架构.md) 第二节）：

```html
<html data-73-theme="portal">   <!-- 门户：绿=成功、琥珀=警示 -->
<html data-73-theme="dev">      <!-- 开发者：青=已完成、金=金额与提示 -->
```

**只有这两个值。** 门户工作台外壳看着像第三套，其实不是——它只用 10 个被冻结的
结构令牌（尺寸、主色、描边、阴影），背景与表面沿用门户侧，状态色跟随当前模式。
理由见 [架构.md](架构.md) 第二节。

只用 DOM 也行——在浏览器控制台里
`document.documentElement.setAttribute('data-73-theme','dev')` 立刻能看到切换，
这比改代码再刷新快得多。

对着一个 `TTag tone="success"` 切这两套主题，应该看到**绿 → 青**的变化。
如果你看到的是同一个颜色，说明组件里写死了色值或者引了 `--el-*`。

### 表单校验

`TForm` 的失败语义与 Element Plus 相反：**失败 resolve `false`，不 reject**。

```ts
const form = ref<TFormInstance>()

async function save() {
  if (!(await form.value?.validate())) return   // 不需要 try/catch
  // …
}
```

也可以直接用 `<TForm @submit="save">`——它会先校验，通过才发 `submit`。

## 六、接入 user_client

**已接入 `user_client` 并完成全站迁移（2026-10-01）。** 接入动的地方见下面「接入动了四处」。
设计取舍见 [架构.md](架构.md) 第七节。

**迁移已完成（2026-10-01）：四个批次全部迁完**，`user_client` 里已无 `element-plus`
依赖、无 `<el-*>` 标签、`--el-*` 也没有供给方了；图标改从本库引（59 个预置图标组件，
与 `@element-plus/icons-vue` 同名），`TLoading` 是这一轮为宿主补的组件。

### 接入动了四处

1. **`package.json`**：`"ui_73info": "link:../ui_73info"`，跑一次 `pnpm install`。
   `pnpm` 建的是**符号链接**（`ls -l node_modules/ui_73info` 能看到 `->`），所以改库源码
   宿主的 HMR 立刻生效——改 `TButton.vue` 后宿主 dev server 会打出
   `[vite] hmr update /@fs/<工作区绝对路径>/ui_73info/src/components/TButton/TButton.vue`，
   不用重启。**若不是符号链接而是拷贝，就说明 link 没生效，得先查这一步。**
2. **`vite.config.ts`**：`optimizeDeps.exclude` 加 `'ui_73info'`；`manualChunks` 里给它
   单独分一块 `ui-73info`（匹配 `'/ui_73info/'`）。它发的是源码、真实路径在
   `node_modules` 之外，不单独挑出来就会落进 `vendor` 兜底。
3. **`main.ts`**：在页面样式**之前**引 `ui_73info/styles.css`。
   迁移期间它排在 `element-plus/dist/index.css` 之后，Element 移除后就是第一位了。
   顺序有语义（令牌要早于消费它的样式），且它只声明 `--73-*` 与 `.t73` 类名空间，
   不碰 `--dev-*` / `--portal-*` / `--profile-*`。
4. **`router/index.ts`**：在既有的 `beforeEach` 里、拿到 `isDeveloperRoute` 之后调
   `applyTheme(isDeveloperRoute ? 'dev' : 'portal')`。
   **判据复用既有那一行**（`to.path.startsWith('/dev') || to.matched.some(r => r.meta.devArea)`），
   不另立规则——实测开发者工作台的真实路径是 `/workbench/developer/*`，
   只看 `path.startsWith('/dev')` 会把它错判成门户主题。
   放在守卫里而不是各页面自己调：主题写在 `<html>` 上，一个页面写错会连累它下面所有组件；
   而且它比页面渲染早，切路由时不会先闪一下上一页的主题。

### 刻意没做的两件事

- **没有引 `alias.css`**（旧变量名桥接层）。它的前置条件之一是「必须在 `<html>` 上挂主题
  属性」，否则 `--dev-*` 会被解析成门户侧色值、开发者页面整片变色。不引它，
  `--dev-*` 仍由 `dev-base.css` 提供，未迁移的页面**一个字都不变**——已实测：
  未迁移的门户页与开发者页上 `.el-button`、`.dev-table th` 的取值与接入前一致，
  且这些页面上 `.t73-*` 元素数为 0（本库的样式表不产生任何视觉足迹）。
  整个文件在迁移完成后应当删除，**它只在「所有页面的旧变量名都准备换成 `--73-*`」时才引**。
- **没有改任何宿主的全局样式**。迁移一页时，那一页自己的 `.el-*` 覆盖要顺手翻译掉
  （见下），但不要动别的页面还在用的那份。

### 逐页迁移的顺序

按**耦合度**而不是业务重要度排：只用 button / icon / tag 的页面先走，
表单族其次，`dialog` / `dropdown` 再次，`table` / `pagination` 最后。
按 user_client 的实际标签用量（实测 1014 处），这条顺序大约是这样：

| 批次 | 组件 | 标签数 | 占比 |
| --- | --- | --- | --- |
| 第一批 | `TButton` `TIcon` `TTag` `TCard` `TEmpty` | 465 | 46% |
| 第二批 | `TInput` `TInputNumber` `TSelect`+`TOption` `TCheckbox` `TRadio` `TSwitch` `TDatePicker` `TForm`+`TFormItem` | 389 | 38% |
| 第三批 | `TDialog` `TDropdown` `TAlert` `TScrollbar` | 75 | 7% |
| 第四批 | `TTable` `TPagination` `TDescriptions` | 84 | 8% |

**四批已全部迁完（2026-10-01）。** 实际的推进顺序与上表略有出入：表单族与
`dialog` / `dropdown` 分两次提交推进，`table` / `pagination` 同期收尾。
`ElMessage` / `ElMessageBox` 换成 `TMessage` / `TMessageBox`；`<el-select-v2>` 1 处
与 `ElConfigProvider` 若干处一并去掉（本库不做 locale 层，见 [架构.md](架构.md) 第八节）。

> 标签数不等于「要改的代码行数」——但**它决定了哪一批最划算**：
> 前两批就能拿下 84% 的迁移面，而且这两批的组件几乎不涉及布局与交互耦合，
> 适合先做、先把信心建立起来。

### 迁一个页面时的动作清单

以第一个迁移页 `BadgeCenterView`（`el-button` + `el-icon`）为例：

1. **把该页的 `el-*` 换成 `T*`**，`import { TButton, TIcon } from 'ui_73info'`。
2. **翻译该页自己的 `.el-*` 覆盖。** 这是最容易漏、事后最难找的一步：那些规则挂在
   `.el-button` 这类选择器上，换掉标签后就静默失效了。`BadgeCenterView` 那颗刷新按钮
   原文走 `.wb-toolbar__icon-btn.el-button` 的一串 `--el-button-*` 变量赋值——
   换标签后全都不再命中，于是形状改由库的 `icon-only` 属性提供。
   **先搜一遍这一页用到的选择器**（`grep '<该页独有的类名>' src/styles/`），
   再决定哪些由库的属性/令牌接管、哪些需要保留。
3. **顺手去掉 `ElConfigProvider`**：本库没有 locale 层（固定文案是中文硬编码），
   所以页面上那一层包装在迁完之后没有存在理由。全站都已经去掉了。
4. **把取舍写进该页顶部的注释**（哪一处与原样不同、为什么），别让后来的人以为是漏改。
5. **对着两套主题各看一次**：该页的主题由路由决定，所以在门户页上看 `portal`、
   在开发者页上看 `dev`，不要手改属性来"凑"视觉效果。
6. **顺手看一眼移动端**：`320 / 375 / 414px` 无横向滚动，触屏命中区 ≥44px。
   `BadgeCenterView` 那颗图标按钮在 `≤640px` 会从 36px 撑到 44px（库的 `iconOnly` 自带）。

### 迁移时会被问到的一件事：`v-model` 的类型

表单控件的 `update:modelValue` 是**联合类型**（`TSelect` 是
`SelectValue | SelectValue[]`，`TDatePicker` 是 `DatePickerValue | DatePickerRangeValue`），
因为它们同时服务单选/多选、单日/区间两种用法。所以绑到窄类型的 ref 上
类型检查会拦下来：

```ts
// ❌ vue-tsc 报错：number | boolean | array 不能赋给 string | null
const status = ref<string | null>(null)
// ✅ 绑到宽类型上，显示时再收窄
const status = ref<SelectModelValue>(null)
```

区间值要取两端时另算一个 `computed`（联合类型里还有非数组那一支，
直接 `range[0]` 会报错）。真实写法见 [`playground/App.vue`](../playground/App.vue)
顶部注释与日期那一段——**那份文件就是迁移时的样板**。

同理，表格单元格插槽里的 `row` 是 `unknown`（列组件不知道行的类型），
要用就显式转一次：

```vue
<TTableColumn label="操作">
  <template #default="{ row }">
    <TButton @click="open((row as Order).id)">查看</TButton>
  </template>
</TTableColumn>
```
