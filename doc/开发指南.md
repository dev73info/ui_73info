## 一、环境与命令

只需要 Node ≥ 20.19 与 pnpm。

| 命令 | 说明 |
| --- | --- |
| `pnpm install` | 装依赖，只需一次 |
| `pnpm dev` | 起 playground（组件预览页），**端口 5180**，`strictPort` 打开——端口被占直接报错，不悄悄换端口 |
| `pnpm type-check` | `vue-tsc --build`。**本库没有 build 步骤**，这是唯一的自动校验入口 |

`pnpm type-check` 会检查 `.ts`、编译 `.vue` 并检查模板里的类型（含组件 props）、
生成声明文件。**改完代码必须跑一次**，它比任何手工检查都便宜。
`playground/` 也在检查范围内。

### playground

`pnpm dev` 起的是 `playground/`：一个把每个组件、每个 `tone`、两套主题都摆出来的单页，
用来肉眼比对。它**不是文档站**，刻意不做导航与分组，目的是一屏看完、切主题时盯着看变化。

几个验证要点：

- **切到 `dev`，看「成功」与「警示」是不是从绿/琥珀变成青/金**。若颜色不变，
  说明组件里写死了色值或引了 `--el-*`。
- **`md` 与 `sm` 按钮的高度应明显不同**（36px / 28px）。高度没变说明尺寸令牌没接上。
- **打开弹窗后**：Tab 应在弹窗内循环、Esc 关闭、关闭后焦点回到「打开弹窗」那颗按钮上、
  背景滚动被锁住（弹窗开着时 `body.style.overflow` 是 `hidden`）。
- **表单区**：直接点「提交」应四条都标红；把昵称填 `admin` 会触发异步校验
  （延迟 400ms 后报「该昵称已被占用」），填别的则通过。

playground 的样式也走 `--73-*` 令牌——它本身就是本库的一个消费方，
不要在它里面写裸色值。

> 手工验证主题也可以不进 playground：在浏览器控制台执行
> `document.documentElement.setAttribute('data-73-theme','dev')` 立刻能看到切换。

## 二、目录与命名约定

```
src/
  index.ts                    出口
  styles/                     样式（见下表）
  theme/index.ts              主题运行时
  primitives/                 行为原语，一个原语一个文件
  components/<Name>/          一个组件一个目录
    <Name>.vue                组件本体
    types.ts                  props / emits 的接口与字段说明
    index.ts                  再导出组件与类型
  types/common.ts             跨组件共用类型（ComponentSize、Tone）
playground/                   pnpm dev 起的预览页（不属于发布内容）
```

| 样式文件 | 职责 |
| --- | --- |
| `styles/tokens.css` | 令牌层。**唯一的色值来源**，两套主题都在这里 |
| `styles/reset.css` | 样式底座，只作用于 `.t73` 类名空间 |
| `styles/alias.css` | 迁移兼容层，按需引入，迁移完删掉 |
| `styles/index.css` | 样式入口，只 `@import` 上面两份（不含 alias），对外是 `ui_73info/styles.css` |

命名规则：

- 组件名 `T` 前缀 + 大驼峰（`TButton`、`TFormItem`）。
- CSS 类名 `t73-` 前缀 + 中划线（`t73-button`、`t73-button__label`、`t73-button--solid`），
  BEM 风格。**前缀不能省**——它是这个库唯一的辨识标记，也是 `reset.css` 的钩子。
- 令牌 `--73-` 前缀 + 中划线语义名（`--73-ink-soft`、`--73-radius-card`）。
- 组件内部私有的中间变量用 `--t73-` + 组件名（`--t73-btn-solid`），
  只在该组件的样式里出现，不进令牌层。

## 三、编码规范

1. **SFC 元素顺序：`<script setup>` → `<template>` → `<style scoped>`**（与仓库既有约定一致）。
2. **禁 `any`**；类型导入一律用 `import type`（`@vue/tsconfig` 开着 `verbatimModuleSyntax`）。
3. **库内一律用相对路径**，不要 `@/`。理由见 [架构.md](架构.md) 第六节——宿主把 `@`
   指到它自己的 `src`，库内写 `@/` 会解析错目录。
4. **组件根元素必须带 `t73` 类**（`<button class="t73-button t73">`），
   它承载字体、墨色、`box-sizing` 基线。
5. **组件层禁止写裸色值、裸 px 的色相关值。** 颜色只从 `var(--73-*)` 取；
   确实需要一个新的色值档位时，**加到 `tokens.css` 并写明它从哪个源文件来**，
   不要在组件里就地写一个。
6. **不接受色值类 prop。** 组件暴露的是语义（`tone="success"`），不是颜色。
7. **`inheritAttrs: false` 的组件要把 `v-bind="$attrs"` 落到根元素上。** `TButton`
   （根是动态组件）、`TInput`（根是包裹用的 div）、`TDialog`（根是 Teleport，不是真实元素）
   都关掉了自动透传，不透传出去会导致调用方写的 `class` / `style` / `data-*` 被静默丢弃。
8. **注释写「为什么」而不是「是什么」**，与仓库其余部分一致；踩过的坑要写进去。

## 四、新增一个组件的步骤

以 `TWidget` 为例：

1. **先定语义，再定样式。** 这个组件在 user-client 里接替谁？它现有规格在哪个文件？
   把「旧写法 → 新写法」的对应关系写进 `types.ts` 的注释里（`TButton` 的 `variant`
   字段注释就是范例）。迁移时这行注释能省掉一整轮试错。
2. **建目录** `src/components/TWidget/`，写三个文件：`TWidget.vue`、`types.ts`、`index.ts`。
3. **组件里只用 `--73-*`。** 遇到缺口回头补令牌，补的时候写清楚来源。
   如果是**两套主题里取值不同**的档位，两边都要补；如果是与主题无关的（尺寸、字号），
   补到 `tokens.css` 第一节那个 `:root` 块里。
4. **需要交互行为时先看 `src/primitives/`** 有没有现成的（焦点陷阱、关闭行为、
   滚动锁定、稳定 id）。要新写原语就放到 `primitives/`，别写在组件里——
   下一个组件会需要同一个。
5. **在 `src/components/index.ts` 里加一行 `export * from './TWidget'`**，
   并在 `src/index.ts` 的 `components` 映射里登记（全局注册插件与测试批量挂载用）。
6. **在 `doc/架构.md` 或 `README.md` 的进度清单里把它从未实现挪到已实现。**
7. **跑 `pnpm type-check`。**

### 组件的必查项

- [ ] 根元素带 `t73` 类
- [ ] 类名是 `t73-` 前缀
- [ ] 没有任何裸色值
- [ ] `disabled` / 加载中这类状态**只降透明度或换令牌**，没有新开一组只用于禁用的颜色
- [ ] 键盘可达：可点元素是原生 `button` 或有 `tabindex` + 键盘处理
- [ ] 有 `:focus-visible` 样式，用 `var(--73-focus-ring)`
- [ ] 需要无障碍名称的（纯图标按钮、弹窗）有 `aria-label` 或 `aria-labelledby`
- [ ] 数字（金额、计数）带 `font-variant-numeric: tabular-nums`
- [ ] 表单控件注入了 `FORM_ITEM_CONTEXT`，能自动参与校验与 `id` 关联
- [ ] 关掉动效（`prefers-reduced-motion`）时有兜底——`reset.css` 已全局处理，组件不必重复

## 五、验证主题与组件

### 主题切换

在页面的 `<html>` 上改属性即可（**必须是 `<html>`**，原因见
[架构.md](架构.md) 第二节）：

```html
<html data-73-theme="portal">   <!-- 门户：绿=成功、琥珀=警示 -->
<html data-73-theme="dev">      <!-- 开发者：青=已完成、金=金额与提示 -->
<html data-73-theme="workbench"><!-- 与 dev 同值，只是名字表达「工作台外壳」 -->
```

只用 DOM 也行——在浏览器控制台里
`document.documentElement.setAttribute('data-73-theme','dev')` 立刻能看到切换，
这比改代码再刷新快得多。

对着一个 `TTag tone="success"` 切这两套主题，应该看到**绿 → 青**的变化。
如果你看到的是同一个颜色，说明组件里写死了色值或者引了 `--el-*`。

### 表单校验

`TForm` 的失败语义与 Element Plus 相反：**失败 resolve `false`，不 reject**。

```ts
const form = ref<TFormInstance>()

async function save() {
  if (!(await form.value?.validate())) return   // 不需要 try/catch
  // …
}
```

也可以直接用 `<TForm @submit="save">`——它会先校验，通过才发 `submit`。

## 六、接入 user-client

**当前尚未接入。** 接入要动的地方（含已具备的部分）见
[架构.md](架构.md) 第七节的表。接的时候按这个顺序：

1. `package.json` 加 `"ui_73info": "link:../ui_73info"`，跑一次 `pnpm install`。
2. `vite.config.ts` 的 `optimizeDeps.exclude` 加 `'ui_73info'`，
   `manualChunks` 里给它单独分一块（别落进 `vendor`）。
3. `main.ts` 里按顺序引入：
   ```ts
   import 'ui_73info/styles.css'
   import 'ui_73info/alias.css'   // 迁移期；挂主题属性之前不要引
   import { applyTheme } from 'ui_73info'
   applyTheme(/* 按路由归属决定 */)
   ```
4. 先只在一个页面里换掉一到两个组件，对着另一套主题切一次，确认视觉与卡顿。
5. 逐页迁移，一页一个提交。**每迁一页，顺手把该页的 `--el-*` 改写与 `.el-*` 覆盖翻译掉**
   ——那些是换框架时最容易漏、事后最难找的部分。

迁移顺序按**耦合度**而不是业务重要度排：只用 button / icon / tag 的页面先走，
表单族其次，`dialog` / `dropdown` 再次，`table` / `pagination` 最后。

## 七、下一步

按优先级：

1. **第二批组件**：定位引擎 → `TSelect` / `TDropdown` / `TPopover` / `TTooltip`，
   然后是 `TTable` / `TPagination`。
2. **接入 `user-client`** 并开始逐页迁移（做法见上一节）。
3. **补测试**：`src/components/TForm/validate.ts` 是纯函数，最适合先补；
   行为原语（焦点陷阱、层栈、滚动锁）值得补一轮 DOM 测试。
   注意：**主题与视觉目前只有 playground 上的人工验证**，没有自动化的截图比对。
